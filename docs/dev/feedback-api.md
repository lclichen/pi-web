# 消息反馈接口需求说明（👍/👎 → AI Gateway）

状态：**客户端已实现，等待网关提供 `POST /api/feedback`**。
前端组件：`components/MessageFeedback.tsx`（复制按钮右侧的点赞/点踩）；
客户端库：`lib/message-feedback.ts`（本地持久化 + 发件箱重投）。

## 交互行为（已实现）

- 每条 assistant 消息（流式结束后）在复制按钮右侧出现 👍 / 👉 两个按钮（行悬停时显示）。
- 点击置为该评价；再次点击同一按钮取消评价；点击另一个按钮切换评价。
- 评价立即写入浏览器 localStorage（`pi-web:message-feedback`），键：`<sessionId>:<entryId>`。
- 每次产生新评价都会尝试投递；失败（含 404/405=网关未上线）静默保留在发件箱，下次评价时重试。发件箱上限 500 条，先进先出。

## 期望的网关接口

### POST /api/feedback

请求（带平台登录 Cookie——网关侧应复用 pi-web 的会话或透传用户身份）：

```json
{
  "feedback": [
    {
      "sessionId": "01a07…",        // pi 会话 id
      "entryId": "b3f9…",           // 会话内该条 assistant 消息的 entry id
      "value": "up" | "down",
      "snippet": "回复前 200 字符预览",  // 仅便于人工核对，非正文
      "createdAt": 1788888888888    // 客户端记录时间（ms）
    }
  ]
}
```

- 批量：每批最多 50 条，客户端按顺序连续批次发送直到发件箱清空。
- 幂等：同一条目重复投递时以最新 value 覆盖（客户端可能对同一 entry 先 up 后 down）。

响应：

```json
{ "accepted": ["<sessionId>:<entryId>", …] }
```

- `accepted`：成功落库的条目键列表（与请求键格式一致）。
- 未出现在 accepted 中的条目客户端会保留在发件箱重试；返回非 2xx 时整批保留。
- 空数组 = 本批没有可接受的（客户端停止本轮发送，下轮再试）。

### 建议的网关侧语义（供 AI Gateway 开发参考）

1. **数据落点**：按 `sessionId + entryId` 主键存储；value 取最后一次写入（upsert）。
2. **维度扩展**（建议网关冗余记录，客户端暂不传但后续可加）：
   - 用户（从 Cookie 解析）、模型（网关在转发链路上最清楚）、时间（服务器时间）。
   - 网关持有请求-响应全文，feedback 表只需外键引用，避免存正文。
3. **对账**：`entryId` 是 pi 会话 JSONL 内的 entry id，网关如有全量请求日志可用
   `sessionId` + 时间窗口对齐到具体的一次 LLM 调用。
4. **取消评价**：客户端不发删除请求——取消只是本地清除；网关如需支持显式撤回，
   可增加 `DELETE /api/feedback?sessionId=…&entryId=…`，客户端后续接入。
5. **导出**：建议提供管理端聚合视图（按模型/按用户/按时间的 up/down 比例）。

## 当前限制（有意为之）

- 纯客户端持久化 → 换浏览器/清缓存丢历史评价（网关上线后由服务端接管即消除）。
- snippet 只有前 200 字符且不加密 → 网关侧务必当作非敏感预览处理。
- 不采集用户消息的评价（用户可编辑/撤回，语义不稳定）。
