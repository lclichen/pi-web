# amedac.ai 全流程测试方案

> 目标：让每一次改动都有「本地可跑、VM 可验、发布前可回归」的标准路径，并可供
> QA 子智能体（`qa-e2e-tester`，见 §6）无人值守执行。方案按环境分层——**不涉及
> 容器/远程实机的改动只需跑 L0+L1**，涉及沙盒/SSH/本机 relay/AppImage 的才上 L2。

## 1. 环境矩阵

| 层级 | 环境 | 覆盖范围 | 启动方式 |
|------|------|----------|----------|
| L0 静态/单元 | 本地（Windows 即可） | 类型、单测、i18n 键位、组件测试 | `npx tsc --noEmit && npm test` |
| L1 本地全流程 | 本地 dev + mock 平台 | 登录/账号、项目 CRUD、配置包、技能、信任、上传（mock 后端）、向导①②③、UI 布局 | §2.1 |
| L2 VM 实机 | 10.99.9.7 | 沙盒容器、SSH 远端、本机 relay、多用户隔离、AppImage 打包与 v4 冒烟 | §4 |

**判级规则**：改动只触及 UI/纯前端/平台无关 API → L0+L1；触及 remotefs 后端、
ssh/relay/sandbox 工具、打包脚本、平台（sandbox-platform）→ 追加 L2 对应小节。

## 2. L1 本地全流程

### 2.1 环境启动（一次性脚本化，子智能体可直接执行）

```bash
# ① 平台：mock 执行器 + 全新 sqlite（顺带验证迁移基线）
cd AgentSandbox/sandbox-platform
DB_SQLITE_PATH=$TMP/local-platform/fresh.db DB_DIALECT=sqlite \
SEED_ADMIN_USERNAME=admin SEED_ADMIN_PASSWORD=LocalDev-9x \
EXECUTOR_KIND=mock HOST=127.0.0.1 PORT=30001 \
WORKSPACE_BASE_DIR=$TMP/local-platform/ws IMAGE_BASE_DIR=$TMP/local-platform/img \
OVERLAY_BASE_DIR=$TMP/local-platform/ovl \
node --experimental-transform-types --no-warnings=ExperimentalWarning src/index.ts &

# ② pi-web dev（读 .env，平台指向 127.0.0.1:30001）
cd pi-web && npm run dev &   # 默认 30141

# ③ 预检
curl -fsS http://127.0.0.1:30001/health        # → 200
curl -fsS http://127.0.0.1:30141/login          # → 200
```

注意：mock 平台没有镜像目录（基线默认不种 demo 镜像），创建沙盒项目会报
「没有可用的镜像」——这是**预期行为**，L1 里沙盒项目仅测到该报错为止。

### 2.2 用例集（L1-xxx）

登录态拿取（后续用例复用）：

```bash
curl -s -c /tmp/c -X POST http://127.0.0.1:30141/api/webauth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"LocalDev-9x"}'    # → 200 + cookie
```

| 编号 | 用例 | 步骤 | 期望 |
|------|------|------|------|
| L1-01 | 登录/登出 | 错误密码 → 登录 → /api/webauth/me | 错误密码 401；正确 200；me 返回 admin |
| L1-02 | 设置→用户 tab | GET /api/account | `authEnabled:true` + 用户信息（username/role） |
| L1-03 | 改密往返 | POST /api/account/password 改 → 旧密码 401 → 新密码 200 → 改回 | 四步全部符合；错误当前密码 401 |
| L1-04 | 项目 CRUD | POST /api/projects（mode:sandbox，无镜像）→ GET 列表 → PUT 改名 → DELETE | 创建报「没有可用镜像」（预期）；列表/改名/删除正常 |
| L1-05 | 配置包导出 | 在项目 home 写 `AGENTS.md` 与 `.pi/skills/a/SKILL.md`、`.pi/ssh.json`（内容随意）→ GET config-export → 解 zip | 含 AGENTS.md 与 skills；**不含** ssh.json/auth.json/sandbox-platform.json |
| L1-06 | 配置包导入 | 对另一项目 POST config-import（用 L1-05 的 zip） | AGENTS.md 与 skills 落盘；报告 added 数正确 |
| L1-07 | 技能 zip 上传 | POST /api/skills/import（含 SKILL.md 的 zip） | 落 `.pi/skills/<名>/`；缺 SKILL.md 的 zip 被拒 |
| L1-08 | 信任流 | 项目 home 放 `.pi/skills/` → GET /api/project-trust?cwd=<home> → POST | GET `{requiresTrust:true,trusted:false}` → POST 后 trusted:true |
| L1-09 | remotefs 上传（mock） | 建沙盒项目会话（ensure_session）→ upload-check → multipart 上传到根与子目录 → list/read | 三段式 200；读回内容一致；不存在目录 404；同名冲突 409 |
| L1-10 | 向导①②③（UI） | 浏览器：新建项目 → SSH 卡片 → 填表 → 测试连接（指 localhost:22 不可达）→ 下一步 | ③ 显示连接失败 + 上一步/重试按钮；不卡死 |
| L1-11 | 会话死循环回归 | 打开主页静置 16s，统计 /api/sessions 请求数 | 新增 0（仅 /api/agent/running 轮询） |
| L1-12 | Host(CLI) 过滤 | 侧栏切 Host(CLI) | 无 沙盒/本地/SSH 项目组；「我的会话」仍可见 |
| L1-13 | UI 布局抽检 | 截图：登录页、主页（浅/深色）、设置各 tab、文件面板右键菜单 | 底部按钮文字横排不竖叠；stepper 完成徽标绿底可见 |

### 2.3 L1 通过判据

全部用例期望达成；每个用例留证据（curl 输出摘录 / 截图文件）到
`evidence/L1-<编号>.<txt|png>`。失败用例记录：复现步骤、实际输出、疑似层级
（前端/路由/平台）。

## 3. （L2 前置）VM 环境要点

- pi-web 部署：`bash scripts/deploy-loopfix.js`（sshdeploy 目录）——构建 + 重启 30141。
- 平台副本在 `~/amedac/sandbox-platform`（git pull 同步）；pi-sandbox-extension
  副本在 `~/amedac/pi-sandbox-extension`。
- 磁盘紧张是常态：打包前 `rm -rf build/package-linux build/package-appspace &&
  npm cache clean --force`，清理 `/tmp/appimage_extracted_*`。

## 4. L2 实机用例集（VM / 真实后端）

| 编号 | 用例 | 关键点 |
|------|------|--------|
| L2-01 | 沙盒容器全链路 | 建沙盒项目（需平台有镜像）→ 会话 prompt → bash 工具在容器内执行（pwd=/workspace）→ 文件面板列容器目录 → 上传到根/子目录 |
| L2-02 | `!`/`!!` 转发 | 沙盒/SSH 会话各发 `!pwd` | 输出为对应后端路径；后端不可用时明确报错而非服务器本机执行 |
| L2-03 | SSH 全链路 | 向导②测试连接（真实主机）→ ③ 自动测试 → ④ 远程目录可视化浏览 → 建项目 → 会话工具 + 终端 PTY + PLAN.md 读写 |
| L2-04 | skills 桥接 | 三种模式会话 read `.pi/skills/.../SKILL.md` | 内容可读（服务端本地桥接） |
| L2-05 | 多用户隔离 | admin/test 双账号：项目可见性、会话空间、host 目录 403、bundles 管理权限、relay 分用户 | 全部按 权限矩阵（见 docs/dev/平台功能检查手册.md） |
| L2-06 | 本机 relay | 配对 → 向导④目录浏览 → 会话工具在本机执行 | 与手册 §连接本地 一致 |
| L2-07 | AppImage 打包+冒烟 | `bash scripts/package-appimage.sh` | 结构校验 OK；磁盘≥3G 时 v4 冒烟通过（前台监护启停 + stop 后监护退出）；否则手动冒烟 |
| L2-08 | AppImage 数据落位 | 抽检生成 platform.env（HOST/BASE_DIR 三件套）、ADMIN_PASSWORD 指定登录、~/.pi 软链刷新 | 与 §打包手册一致 |

## 5. 回归范围选择

- **冒烟集**（日常小改）：L0 + L1-01/04/09/11/12。
- **标准集**（功能改动）：L0 + L1 全部 + 相关 L2 小节 + S 系列中与改动面相交的用例。
- **发布集**（打包/平台/权限改动）：全部 + 手册全量走查 + S 系列全量。

## 5a. 安全回归用例（S 系列，2026-09-04 增补）

> 触发条件：改动触及鉴权/会话/relay/平台中间件时必须跑对应小节。
> 环境：L1（本地 dev + mock 平台）即可执行 S-01…S-08；S-09/S-10 需 L2。

| 编号 | 用例 | 步骤 | 期望 |
|------|------|------|------|
| S-01 | 伪造 cookie | 不登录，携 `Cookie: pi_web_sid=forged` GET /api/sessions、POST /api/terminal/create、GET /api/cwd/browse | 全部 401/403，**不得**返回数据或创建终端 |
| S-02 | 文件围栏 fail-closed | 伪造 cookie GET /api/files/<任意路径> 与 PUT 写入 | 401；不得列出/读写宿主任意路径 |
| S-03 | 越权会话 | 用户 A 登录后访问用户 B 的会话 remotefs/remoteterminal（sid 已知） | 404/403；终端 input/close/events 均拒绝 |
| S-04 | relay token 原型链 | 对 relay WS 口用 `?token=toString`、`?token=constructor` 尝试升级 | 连接被拒（401 后 destroy） |
| S-05 | rpc/stream 软失败 | 伪造 cookie POST /api/agent-relay/rpc/stream | 401，不产生对 agent 的调用 |
| S-06 | 配对限速 | 连续 15 次错误 pairing code POST relay 口 /pair/exchange | 前 10 次内出现 429/限速响应；正确 code 仍可用 |
| S-07 | 登录限速 | 同一 IP+用户名连续 12 次错误密码 | 出现限速响应（429/420），正确密码在锁定窗口内同样受限 |
| S-08 | 平台 fail-closed 启动 | 平台不设 JWT_SECRET/EXECUTOR_KIND 启动 | 正常启动但日志含随机 secret 告警；`EXECUTOR_KIND` 未显式且无 ssh/apptainer 时**启动失败**并提示 |
| S-09 | PTY ticket | L2：直接带平台长期 token 连 /pty | 升级被拒；先取 ticket 再连成功；ticket 复用第二次被拒 | 
| S-10 | mock env 白名单 | mock 平台内 bash `env` | 输出**不含** JWT_SECRET/SEED_ADMIN_PASSWORD/SSH_* 等平台机密 |

S 系列证据同样落 `evidence/S-<编号>.txt`（curl 全文）。

## 5b. 多机连接用例（M 系列，2026-09-04 增补）

> 触发条件：改动触及 relay/agent/项目连接绑定。L1 可用两个本地 agent 实例
> （不同 PI_AGENT_HOME 与不同 workspace root）模拟两台机器。

| 编号 | 用例 | 步骤 | 期望 |
|------|------|------|------|
| M-01 | 双机配对 | 同一用户先后完成两次配对（agentA、agentB） | machines 列表含两台，均 online；旧单机数据自动迁移为一台 |
| M-02 | 按项目绑定 | 项目 P1 绑 agentA、P2 绑 agentB，各开会话执行 fs.list | P1 命中 A 的 root，P2 命中 B 的 root（返回的 workspaceRoot 不同） |
| M-03 | 单机回落 | 用户只有一台机器时项目不选机器 | 会话正常路由到唯一机器（兼容旧行为） |
| M-04 | 离线机器 | P1 绑定的 agentA 下线 | machines 列表 A=offline；P1 会话工具报"机器离线"，P2 不受影响 |
| M-05 | 重连逐出 | agentA 断开后同 machineId 重连 | 新连接可用，旧 pending 拒绝；**不影响** agentB |
| M-06 | 解绑吊销 | machines 面板对 agentB unpair | B 的 WS 断开且 token 失效（重连被拒）；A 正常 |
| M-07 | 终端隔离 | P1/P2 各开远程终端并输入 | 输出各归各屏；A 下线只影响 P1 终端 |
| M-08 | 改名持久化 | rename 机器后重启 pi-web dev | label 保留 |



## 6. QA 子智能体（qa-e2e-tester）

- 定义文件：`pi-config/agent/agents/qa-e2e-tester.md`（随包分发，装到
  `~/.pi/agent/agents/` 即全局可用；也可放项目 `.pi/agents/`）。
- 建议模型：带视觉能力的模型（如 Qwen3.8-27B）——用例 L1-10/13 与 L2 的
  UI 判读需要看截图。frontmatter 不写死 `model`，由部署侧指定。
- 调用方式（主智能体或人工）：
  ```
  用 qa-e2e-tester 执行【冒烟集/标准集】，环境：L1 本地 dev（或 L2 VM），
  证据目录 <path>，报告写入 <path>。
  ```
- **职责边界**：只执行测试与报告，不修复。修复由主智能体/人在其报告上进行。

## 7. 证据与报告规范

- 证据目录按用例编号命名；截图 PNG、接口输出 TXT。
- 报告（markdown）结构：环境信息（git rev/端口/账号角色）→ 结果总表
  （编号/结果/证据路径）→ 失败详情（严重度 P0-P3、复现步骤、期望 vs 实际、
  疑似层级）→ 建议回归范围。
- 严重度定义：P0 主流程不可用/数据丢失/越权；P1 主流程有损但有绕行；
  P2 次要功能或体验；P3 文案/样式。
