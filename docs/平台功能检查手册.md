## 2. 新建项目（三种方式）

向导入口：侧栏顶部「新建项目」按钮 → 远程连接向导（①选择方式）。

### 2.1 连接沙盒 🔧（需 Apptainer + 平台已配镜像）
1. 选「连接沙盒」→ ② 填项目名、选镜像（或复用已有容器/云盘初始化）→ ③ 连接中（自动创建/供给容器）→ ④ 目录固定 `/workspace` → 完成。
2. ✅ 侧栏出现项目节点（沙盒徽标 + 容器状态点）；会话创建后在容器 `/workspace` 内执行（文件面板可见容器内容）。
3. ✅ 容器停止状态下创建会话 → 项目行显示容器状态（运行中/已停止/无容器）。

### 2.2 连接本地机器 🔧（需先完成 §7 配对）
1. 选「连接本地」→ ② 填项目名 → ③ 连接中（**向导内嵌配对面板**：显示下载 Agent、配对码、后台常驻三步；已配对则自动跳到 ④）。
2. ✅ 配对成功后自动进入 ④，填本机工作目录（Agent 侧路径）→ 完成。
3. ✅ 会话中文件面板/终端均落在本机工作目录（remote 模式）。

### 2.2+ SSH 模式（远程主机）

1. 选「SSH 连接」→ ② 填 项目名称 / 主机地址 / 端口 / 用户名 / 密码或私钥。
2. ✅ 「测试连接」：点击后尝试真实 SSH 连接（whoami 往返），成功显示连接用户，失败显示具体原因（如 All configured authentication methods failed = 密码错误）。
3. ✅ 下一步 → ③ 创建项目（凭据写入 .pi/ssh.json，0600）→ ④ 填远程工作目录（如 /root/projects/demo）→ 完成。
4. ✅ 会话中 Agent 的 bash/read/write 等工具经 SSH 在远程主机工作目录内执行（让 Agent 运行 `pwd` 应返回远程目录）。
5. ✅ 文件面板经 SFTP 列出/读写远程文件（虚拟根 = 远程工作目录；服务器侧项目 home 绝对路径自动映射）。
6. ✅ 隔离：凭据 0600 存项目配置、不随配置包导出；会话 owner 校验与其他模式一致。

### 2.3 打开服务器目录（仅 admin）
1. admin 在 ① 可见「打开服务器目录」卡片；**test 在 ① 不可见此卡片**。
2. ✅ 选择目录后直接创建 host 模式会话；侧栏该目录会话归入「Host 分组」（见 §4）。

### 2.4 复制为新项目
1. ✅ 项目菜单「复制为新项目」→ 生成副本（含 .pi/ 配置快照，凭证重写）。

## 3. 会话基础流

1. ✅ 项目节点 → ＋ 新建会话 → 发送一条消息 → 助手回复流式出现（模型可用时）。
2. ✅ 会话重命名（行内菜单）、删除（确认框）、置顶（置顶项排最前）。
3. ✅ 队列：会话运行中再发消息 → 进入 steering/followUp 队列并显示；`clear_queue` 生效。
4. ✅ 分支：fork/clone 生成新会话并在树中可见；navigate_tree 切换分支。
5. ✅ 压缩：手动 compact 后上下文占用下降；压缩摘要条目在会话中可见。
6. ✅ 编辑审批：正常模式下编辑/命令触发审批卡；批准/拒绝均正确生效。

## 4. Host (CLI) 空间（仅 admin）

1. ✅ admin 侧栏项目树顶部出现「我的会话 | Host (CLI)」切换；test 无此开关。
2. ✅ 在服务器上跑 `pi -p "..."`（CLI，任意目录）→ 切到 Host 空间 → 该会话按目录分组出现（Host 徽标）。
3. ✅ Host 目录组：**＋** 直接在该目录建 host 会话；**⋮** 菜单含 新建会话 / 导入项目配置 / 导出配置包 / 复制路径 / 在文件面板浏览。
4. ✅ 项目列表在两个空间都保留（host 空间下项目显示空态「暂无会话」但仍可 ＋ 建会话）。
5. ✅ test 请求 `?space=host` → 返回空列表（服务端栅栏）。

## 5. 配置包导出 / 导入

### 5.1 项目配置包
1. ✅ 项目菜单「导出配置包…」→ 下载 `<项目名>-config.zip`。
2. ✅ 解包检查：含 `.pi/`（agents/skills/extensions/models.json）与 `labs/`、`manifest.json`；**不含** auth.json、sessions/、.git。
3. ✅ 项目菜单「导入项目配置…」→ 拖入或选择 zip → 报告 新增/覆盖 数量与文件清单。
4. ✅ 导入含 node_modules 的包（离线分发）：extensions 依赖随包恢复，无需 npm install。
5. ✅ 安全：构造含 `../` 路径或超 200MB 的包 → 报错且项目原配置不受影响；auth.json 在包内 → 被静默剥离。

### 5.2 Host 目录配置包（仅 admin）
1. ✅ Host 分组 ⋮ 菜单 → 「导出配置包…」→ 下载该目录的 config.zip。
2. ✅ 「导入项目配置…」→ zip 解包合并进该目录（.pi/、labs/）。
3. ✅ 无配置的目录导出 → 明确报错「该目录没有可导出的配置」。
4. ✅ test 用户调用 `/api/host/config-export` → 403。
5. ✅ 栅栏外目录（如 /etc）→ 403 Access denied。

## 已知限制 / 非目标

- SSH 模式：聊天中 `!`/`!!` 前缀的原生 bash 与交互式终端暂未走 SSH（会话级 bash 在服务器执行）；远程操作请让 Agent 调用 bash 工具。

- SSH 连接方式为预留入口（未实现）。
- Host 目录组是动态目录聚合，非持久化项目：不支持置顶/重命名（需要时用「新建项目」落成正式项目）。
- 配置包不携带凭证（auth.json 双向剥离）——目标机需自行配置模型凭证。
- Windows 本机跑构建脚本会有 symlink/路径类测试失败（与 upstream 基线一致），Linux 构建机不受影响。
- zh-TW 平台新增键暂用简体文案（文件内有 TODO 标记）。
