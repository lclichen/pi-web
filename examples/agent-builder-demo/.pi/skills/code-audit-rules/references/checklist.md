# 巡检检查清单（逐项核对）

> 仅在需要逐项核对时加载本文件；SKILL.md 给出维度即可开始工作。

## A. 安全（逐项）

- [ ] **命令拼接**：`exec/execSync/spawnSync` 是否拼接了外部输入？优先 `execFile + argv`。
- [ ] **路径拼接**：用户可控路径是否做归一化与根目录校验（`..` 穿越、绝对路径逃逸）？
- [ ] **凭据**：源码/配置里是否有硬编码 token/password？测试夹具除外（需 allow 标记）。
- [ ] **SQL/模板注入**：SQL 是否全部参数化？模板渲染是否对外部输入转义？
- [ ] **权限默认**：新建文件权限、服务绑定地址（0.0.0.0?）、CORS/开启的调试接口。
- [ ] **反序列化/解析**：`eval`、`new Function`、YAML/JSON 解析不可信输入时的防护。

## B. 可维护性

- [ ] **空 catch / 吞错**：`catch {}` 或仅 console.log 后继续，确认有兜底语义。
- [ ] **重复实现**：同一段逻辑出现 ≥3 处，或两份几乎相同的函数。
- [ ] **超大文件/函数**：单文件 > 800 行、单函数 > 80 行时给出拆分建议。
- [ ] **TODO/FIXME/HACK**：优先看带日期或安全标记的；陈旧 TODO 建议闭环或删除。
- [ ] **隐式全局状态**：模块级可变缓存/单例是否跨请求泄漏？清理时机是否明确？

## C. 测试

- [ ] **改动 vs 测试**：`audit_collect` 报告的变更文件是否有同名/同目录测试？
- [ ] **断言质量**：只断言 `not undefined`/快照大对象而无关键字段的测试视为弱覆盖。
- [ ] **夹具漂移**：测试数据是否复制自真实文件且未同步（搜过期的 schema/字段名）。
- [ ] **失败网络**：测试是否依赖外网/随机端口而无法在 CI 稳定跑通？

## D. 报告落地

- [ ] 每个"高"级项都有：位置、触发条件、影响、最小修复建议。
- [ ] 覆盖率结论标注来源（coverage-analyst 或自检），不混写。
- [ ] 结尾给 1-3 条"下一步"，按投入产出排序。
